# Design: Image Editor + Spend Tracking + Session Grouping

Generated by /plan-ceo-review on 2026-03-18
Branch: main | Mode: SELECTIVE EXPANSION

## Overview

Three features shipping together:
1. **Image Editor** — Non-destructive color grading, grain, vignette, RGB chromatic split with Sharp worker thread
2. **API Spend Tracking** — Per-key budget enforcement with Gemini pricing, daily chart, per-character breakdown
3. **Gallery Session Grouping** — Batch images grouped by sessionId with bulk actions

## Architecture

```
CLIENT (React)
├── ImageEditorPage → ImageEditor (sliders, presets, undo/redo, compare)
├── GalleryPage → session grouping toggle, "Edit" + "Apply last edit" buttons
├── ApiKeysPage → spend card, per-key spend bars, daily chart, per-character breakdown
└── api.js → saveEdit(), getSpend(), resetSpend()

SERVER (Express)
├── routes/gallery.js → POST /:id/edit (worker pool, size=1, cancellation)
├── routes/keys.js → GET /spend, POST /spend/reset
├── workers/imageEditWorker.js → Sharp pipeline (5 passes max)
├── services/apiKeyManager.js → per-key spend, daily log (90-day cap), budget enforcement
├── services/geminiService.js → _checkBudget() + _trackTextSpend() + _trackImageSpend()
└── services/galleryManager.js → save() with sessionId
```

## Implementation Items (from review)

### Build Now
1. Worker pool (size=1) with request cancellation
2. Error logging on 3 silent catch blocks
3. Input validation (clamp params) on edit route
4. DRY: extract shared presets module + SpendBar component
5. Remove dead code (editImage, editPreviewUrl in api.js)
6. Fix compare mode to use server preview URL when available

### Key Decisions
- Worker thread: single reusable worker with message-based cancellation (not spawn-per-request)
- Spend log: daily granularity, 90-day rolling window, stored per-key
- Compare mode: uses server-rendered preview (not CSS-only) for accuracy
- Budget default: $300 per key, user-resettable
